| 2026-07-30 | brain | **Feature builds fan out — `/build-feature` + [`.claude/workflows/build-feature.js`](../.claude/workflows/build-feature.js) orchestrate the harness operators in parallel.** The observation the design rests on: most of a feature's apparent ordering (schema → repo → procedure → UI → tests → verify) is a **compile** dependency, not an **information** dependency. Once the interface is fixed, the server lane and the UI lane need nothing from each other, and every verification lane needs only the finished tree — so the *only* genuinely sequential step is fixing the contract. Five phases: **Orient** (3 read-only lanes at once — `brain-navigator` reading list · a trace of the nearest existing feature · a UI tier-1-vs-tier-2 check; none can conflict and the architect needs all three) → **Contract** (an architect returns a structured contract: source-level Effect Schema shapes, repository signatures, procedure names + auth level, tagged errors with their `tagToTRPC` codes, plus the per-lane **file-ownership map** and acceptance checks; then one writer lands the shared schema file) → **Build** (up to 5 lanes concurrently — typically data · api · ui · e2e — each dispatched to the right operator, `recipe-runner` for schema/repo/procedure, `ui-builder` for anything user-visible, `test-author` for tests) → **Verify** (`verify-done-runner` ‖ `effect-ts-enforcer` ‖ `span-instrumenter` ‖ `feature-verifier` ‖ `design-critic`, all at once, browser lanes each owning a port and using `CI=1` for the dev server) → **Close** (one high-effort synthesis: what is demonstrably true *with evidence*, blocking P0/P1s, lane collisions, **human decisions it refuses to make itself**, and the brain updates still owed). ~13 agents for a UI feature, ~9 server-only. **The constraint that makes it safe:** parallel writers own **disjoint paths** — the contract assigns ownership, every lane prompt repeats its own fence with an instruction to stop rather than edit outside it, and a reported collision is a P0 to be re-run sequentially. The workflow deliberately **does not commit, does not touch brain state and does not decide** anything a human should; the command documents the after-steps (fix P0/P1s by re-dispatching the owning agent, answer the human decisions, run `/verify-done` yourself, then brain updates, then commit) and the when-not-to-use list (one-file changes, an unknown interface, a red baseline, exploratory work — fan-out is for when the shape is known). |

| 2026-07-28 | brain | **Test authoring becomes a delegated, gated step in the verification loop — `test-author` sub-agent + `99-verify-done.md` §1.** Problem: tests were written by whichever agent happened to touch the code, with no shared standard for what earns one. The failure mode is coverage padding — tautologies, assertions on mock return values, near-clones of tests that already exist — which inflates the count while leaving real business-logic regressions uncaught. New [`.claude/agents/test-author.md`](../.claude/agents/test-author.md): its central rule is a **gate** — every proposed test must name the specific wrong edit it would catch, or it does not get written. Priority order is tagged-error paths → business invariants → boundary/refinement rejections (the boundary itself, not an interior value) → *which* drizzle call ran (via `chainableSpy`) → non-mutation. Tautologies, mock theater, snapshots, library tests, duplicate coverage, and non-determinism are banned outright; it greps the sibling `__tests__/` before adding and **prunes** redundant tests, so the count may go down.
