## Console

Collected by the script's `console` + `pageerror` + `response` listeners, split by cause:

- **jsErrors** — one entry, on the **login page** (not the feature surface):

  > `A tree hydrated but some attributes of the server rendered HTML didn't match the client properties. … <input … data-testid="login-email" …> - style={{caret-color:"transparent"}} …`

  The diffed attribute is `caret-color: transparent` on the login form inputs. Grep backstop: `caret-color` / `caretColor` / `_R_` have **no match anywhere in `app/`** — this is the browser's built-in password manager hiding the caret on a focused input (clean bundled-Chromium profile, `--disable-extensions`, so not an extension; it fires only when a field is focused during hydration, hence the flakiness). **Classified: environment artifact per the agent's console policy — noted, not a FAIL.** (Correction to the earlier same-day doc, which had attributed this to a `useId` mismatch from a truncated trace; the full diff shows `caret-color`.)

- **networkErrors** — none. No 4xx/5xx on any step (the previous run's 502 on `analytics.getAiInsights` is gone after the fix).
