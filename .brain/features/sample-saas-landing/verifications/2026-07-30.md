## Findings for main thread

Two real defects found by the walk, both fixed and re-verified in this same session:

1. **Horizontal page overflow at 390px** (`scrollWidth 491`). The per-element probe pinned it on the top bar's control cluster (`width 323, right 491`) — wordmark + demo chip + sign-in + CTA + language switcher + theme toggle do not fit a phone. Fixed by dropping the chip and the sign-in link below `sm` (the hero already carries a sign-in CTA). A `min-w-0` was also added to the board's scroll container and frame so the table's `min-w-[34rem]` can never escape its grid track — belt and braces, since the table itself was not the culprit.
2. **First CTA check reported no navigation.** Not an app defect — the script screenshotted before the client navigation settled. Re-tested with an explicit `waitForURL("**/sign-up")`; the CTA navigates correctly.

Pre-existing repo gap, **not** introduced here and out of scope for this change:

- **`/zh/demo` (and `/zh/`) do not switch locale.** `i18nServer.getLocale(request)` reads the `?lng` search param, the cookie and the `Accept-Language` header — it never reads the `:lng` path param, so the `...prefix(":lng", [...])` routes in `app/routes.ts` serve English. Confirmed identical on the pre-existing `/` route (`curl /zh/` returns "serious starting point" in English), so this is a repo-wide i18n-detection gap, not a demo-route bug. Worth a follow-up: pass the route param into the detector or drop the prefix routes.
