# Languages

The app speaks English and Chinese (`supportedLngs` in `app/lib/constants/i18n.ts`). The server picks the locale from the locale cookie or the request headers (`app/i18n/i18n.server.ts`); the language switcher (`app/components/language-switcher.tsx`) changes it through `POST /api/set-locale` (`app/routes/api/set-locale.ts`).

## Why

- **Only the public pages have a locale prefix.** Home, sign-in and sign-up answer at the root in the default locale and again under `/:lng`, so a search engine can index each language. The API routes, the dashboard and the admin area have no prefix and translate in the browser only; the dashboard and admin layouts also require a session.
- **A route lists every namespace its page renders.** A route's `handle.i18n` is what loads on a direct or hard navigation, so it names the namespaces of the components it renders too. The kitchen sink lists `admin` because `SiteHeader` takes its GitHub link text from it.
- **The switcher never calls `i18n.changeLanguage`.** It posts to `/api/set-locale` with `useFetcher`. The action sets the locale cookie, React Router revalidates the loaders, the root loader detects the new locale, and `useChangeLanguage(loaderData.locale)` in `app/root.tsx` switches the live i18next instance. No reload, and nothing fights `useChangeLanguage`, which reverts a language that does not match the loader's.
- **One cookie definition, one writer.** `localeCookie` (`app/i18n/i18n.ts`) is shared by the server's detector and the `set-locale` action. Its format belongs to `createCookie` (base64-encoded JSON), so every write goes through `localeCookie.serialize`, never `document.cookie`, and the reader and the writer cannot disagree. It lasts `LOCALE_COOKIE_MAX_AGE_SECONDS`, one year.
- **Theme labels come from their value.** `themeItems` (`app/components/theme-toggle.tsx`) is shared by the theme toggle and the theme submenu in `nav-user.tsx`, so both list the same choices with the same icons. Each `value` is also the key suffix in the `common` namespace (`theme.light`, `theme.dark`, `theme.system`), so a render site calls `` t(`theme.${value}`) `` and holds no label of its own.
